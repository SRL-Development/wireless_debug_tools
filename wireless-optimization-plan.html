01 定位与边界

一句话定位：把「图纸 + 射频数据 + 故障证据」放在同一张空间底图上，让无线问题从「凭经验猜」变成「看得见、可回溯、可验证」。

与 NetDeviceUI 的关系

复用既有自研 SNMP v2c 轮询框架、设备清单、告警通道、Windows exe 打包与本地 Web UI；新增无线专属的数据模型、空间引擎、规则库与优化模块。可作为独立子模块启停，不影响有线监控主链路。

核心差异点

现有 Zabbix / 通用监控以「设备是否在线、指标是否越阈」为主；本工具以空间维度和用户体验维度为主，回答「哪里信号差、为什么差、改哪个参数」。

明确不做

不替代专业预测规划软件的完整射线追踪与 3D 建模；不做 802.11 协议栈全量解码（空口抓包仅做证据提取）；不做自动下发变更（只生成可回滚的变更清单，由人审批执行）。

设计原则：数据可追溯（每个热力值都能回查原始样本）、结论可解释（每条故障结论附带证据链与置信度）、变更可回滚（优化建议先仿真对比再出单）、离线可运行（内网无外网环境完整可用）。

04 总体架构

单机部署、分层解耦：Windows 主机上运行采集与计算服务，浏览器访问本地 Web UI，全部数据留在内网。

部署形态：一台 Windows 主机承载采集服务 + 计算服务 + 静态前端，浏览器访问 127.0.0.1；通过现有 FortiClient VPN 或直连主机可达现网设备。所有外部访问均为只读，凭据用 Windows DPAPI 加密存储。若后续要多站点集中，仅需把 ③ 换为集中时序库、把 ① 拆为分布式采集器，上三层不变。

06 热力图引擎（技术核心）

推荐路线：传播模型给先验 + 实测打点做残差校正，而非纯插值。这样在打点稀疏的楼层也能给出合理分布，在打点密集处收敛到实测真值。

6.1 坐标标定与墙体建模

  1. 图纸导入：PDF 经 PyMuPDF 转高 DPI 位图；DXF 用 ezdxf 提取墙线图层；PNG/JPG 直读。保留原图作为不可变底图。
  2. 坐标配准：人工放置 ≥ 3 个控制点（图纸像素 ↔ 实际米坐标），求最小二乘仿射变换；记录比例尺与误差（RMSE），超过阈值提示重标。
  3. 墙体矢量化：人工/半自动描墙并标注材质，按频段给出单墙衰减参考值（示例：石膏板 ~3 dB、砖墙 ~6–8 dB、混凝土 ~10–15 dB、金属/玻璃幕墙 ~15 dB+），5G/6G 衰减高于 2.4G；数值可现场用实测打点反演校准。
  4. AP 落图：录入坐标、挂高、天线方向图（先简化为全向 / 定向两档），作为预测模型输入。

08 无线优化引擎

输入是 AP 冲突图与实测/预测覆盖，输出是逐 AP 的变更清单 + 预期增益 + 回滚项，而非直接下发配置。

信道与带宽规划

  • 构建 AP 冲突图（共信道可见 + 邻接重叠），转为图着色问题：贪心初始解 + 局部搜索/模拟退火迭代，目标为最小化加权同频干扰
  • 2.4G 限定 1/6/11、20 MHz；5G/6G 按 UNII 与 DFS 约束，权衡 20/40/80/160 MHz：带宽越大速率越高但可用信道越少
  • DFS 信道单独标记，结合历史雷达跳变记录决定是否规避
  • 6E/6GHz（若现网具备）优先引导新终端，缓解 5G 压力

功率与覆盖优化

  • 目标：边缘 RSSI 达标 + 相邻 AP 重叠度约 15–20%，避免功率过大导致粘滞与同频干扰
  • 以预测模型做「改前 / 改后」差分热力图，量化达标面积变化与盲区变化
  • 提高最小基本速率（禁用 802.11b 低速率）压缩低速终端空口占用
  • 输出 AP 增删/移位建议与天线朝向调整建议

漫游与负载

  • 802.11k 邻居表 / 802.11v BSS 过渡 / 802.11r 快速漫游的启用与兼容性检查（注意老旧终端兼容风险）
  • 最小 RSSI 踢除阈值、Band Steering 策略、AP 间负载均衡阈值
  • Airtime Fairness 与组播速率优化，语音业务单独 SLA 模板

变更闭环

  • 变更前自动保存配置快照与当前热力图
  • 变更清单按 AP / 射频逐条列出，含命令或 API 参数、预期增益、影响范围、回滚项
  • 变更窗口后自动生成复测打点任务，差分对比验证增益，未达标则提示回滚
  • 归档为「站点优化档案」，供后续同类场景复用
与厂商 RRM（自动射频管理）的关系：本工具不替代 RRM，而是评估与校验 RRM 的结果，或在静态规划场景下给出人工方案。若现网启用 RRM，优化模块应先读取其配置与历史调整记录，避免给出相互冲突的建议。

12 风险与待确认开放项

技术风险

  • 厂商差异：各 WLC API 字段与能力差异大，客户端级 RSSI 未必都能取到；需先做现网能力摸底
  • MIB 覆盖：老型号 AP 的私有 MIB 可能缺失关键指标，只能降级到接口级统计
  • 墙体信息缺失：无材质标注时预测模型精度受限，必须显式标注置信度
  • SNMP v2c 安全：community 明文、无认证加密，限定只读 + 内网 + ACL
  • 数据合规：客户端 MAC、位置与抓包涉及个人信息，默认脱敏与最小留存

需要你确认（影响 P1 排期）

  • 现网无线品牌/型号与控制器版本清单，是否已部署 6E / 6 GHz
  • 能否提供只读 API 账号与 SNMP community，以及接口文档/测试环境
  • 图纸格式与来源（PDF/PNG/DXF）、是否含比例尺与墙体材质信息
  • 规模：站点数、楼层数、AP 总数、并发客户端数
  • 现场打点用什么终端、是否允许在工具内做移动端打点
  • 是否已启用厂商 RRM；优化是否允许人工静态规划
  • 是否需要与既有 NetDeviceUI 共用同一进程/端口，还是独立 exe
  • 优先落地的第一个真实故障场景（用于 P1 验证）

15 SSID 全局维度与热力图实时重算（v0.7）

来自 P0 原型试用反馈的两处缺口：现场排障是以「某个 SSID」为单位进行的，而图纸热力图在移动 AP 后没有重绘。前者是功能缺失，后者是交互缺陷，两者都直接影响结论可信度，因此单独成节说明设计与验证。

15.1 为什么 SSID 必须是一等数据，而不是一个显示标签

同一个楼层、同一批 AP，往往同时广播员工、访客、语音、IoT、AGV 等多个 SSID，各自绑定不同 AP 组、频段、VLAN、认证方式与接入门限。如果热力图只算「所有 AP 的物理覆盖」，就无法回答「语音终端在这个角落能不能用」这类真实问题：Voice SSID 只在 5 GHz 的 5 台 AP 上广播，物理上有 2.4 GHz 信号不等于语音可用。因此 SSID 必须作为贯穿全工具的全局分析维度参与计算，而不是给报告加个标题。

15.2 SSID 数据模型

字段含义下游作用

ap_ids广播该 SSID 的 AP 集合（空 = 所有 AP）热力图只对这些 AP 求传播；干扰分析只统计这些 AP 的同信道冲突；AP 列表标注「本 SSID / 不广播」

15.4 热力图实时重算机制（缺陷修复）

原缺陷：拖动 AP 只重绘了 AP 标记图层，热力图 canvas 沿用上一次计算结果，视觉上「AP 动了、颜色块没动」。修复采用两级重算，兼顾即时反馈与模型精度：

① 拖动中 · 即时轻量预览

  • 每个 mousemove 用 64×45 低分辨率网格、只算自由空间路径损耗与 AP 功率，直接刷新热力图 canvas
  • 状态栏显示「拖动预览（轻量模型）」，明确这不是最终结论
  • 同样按当前 SSID 过滤 AP 与频段，避免预览与实际结果不一致

② 松手后 · 完整模型重算

  • 统一入口 markDirty()，280 ms 防抖后调用完整 /api/heatmap
  • 完整模型含多墙材质衰减、实测残差 IDW 校正、留一交叉验证 RMSE、干扰噪声抬升与 SINR 图层
  • 「自动重算」开关默认开启；关闭时状态栏提示需手动点「计算热力图」，不静默使用过期结果

16.10 近场保护与「本机当前 SSID」（v0.10）

现场试用反馈：按示例楼层模板拖动 AP 后，离 AP 近的地方反而出现盲区，远处却正常；另外演示用的 SSID 是虚构名称，与现场口径对不上。前者不是渲染问题，而是把「布局相关的实测残差」当成「固定空间偏移场」导致的模型错误。v0.10 同时修正模型、并把这台电脑正在使用的 SSID 变成默认分析对象。

① 根因：残差定义为「实测 RSSI − 当前布局的模型预测」，本身随 AP 位置变化。旧实现每次都按新布局重算残差，再用 1/d⁴ 的 IDW 把它插值成全图固定偏移（限幅 ±18 dB）。把 AP 拖到某个打点上时，该点预测骤升到 −23 dBm、实测仍是 −51 dBm，产生约 −28 dB 的残差；这个大负值在 AP 脚下权重最大，把近场整体压低 18 dB，于是「越近越像盲区」。次要因素：AP 贴墙时极短射线可能连穿多段墙，累加到 42 dB 衰减上限，在墙边 AP 脚下形成第二个假洞。

修复点做法与物理依据
残差稳健化以中位数代表系统性偏差（发射功率标定、统一墙损偏差），Huber 软限幅 ±10 dB；偏离中位数超过 12 dB 的打点判为「与当前布局失配」，权重降到 0.15，并在评估区提示数量。单个旧打点不再能主导一片区域。
近场保护 3 m残差校正量按 (d_AP / 3 m)² 渐入，AP 脚下校正权重为 0，完全由传播模型决定。近场本来就是直射 / 绕射主导，实测校准只对中远场阴影衰落有意义。
近场墙损折减AP 3 m 内墙损按 35%→100% 渐入，避免贴墙 AP 因射线连穿多段墙而在脚下挖洞；3 m 以外恢复完整多墙衰减。
口径一致性AP 重叠度改用未校正的传播先验值计算；留一交叉验证 RMSE 与渲染共用同一套残差权重；新增开关可关闭残差校正，直接对比纯传播模型。

16.12 真实空口扫描与干扰评估（v0.12）

前 11 节里「现场连接」「干扰分析」都是模拟数据。本节补上唯一一条真实无线数据链路：直接调用 Windows 原生 WLAN 接口扫描本空间空口，把 SSID（含隐藏）、信道、带宽、RSSI、加密方式、BSS Load 读出来，再算成可判读的质量与干扰结论。

采集：为什么用 Native WiFi 而不是 netsh

  • netsh wlan show networks 只给名字、信号条和加密，没有 BSSID、没有信道、没有带宽、没有 BSS Load，且默认隐藏空 SSID 条目
  • 改用 wlanapi.dll：WlanOpenHandle → WlanEnumInterfaces → WlanScan → WlanGetNetworkBssList
  • 逐条解析 WLAN_BSS_ENTRY 与紧随的 IE：DS Parameter(3) 取信道、HT Cap/Op(45/61)、VHT Op(191)、HE Op(255/36)、RSN(48) 与 WPA 厂商 IE 取加密、BSS Load(11) 取终端数与信道利用率
  • 字段偏移按实测标定（条目步长 360 B，SSID 在 0/4、BSSID 在 40、RSSI 在 56、频率在 92、IE 偏移在 352/356），并用 dwTotalSize 兜底，避免不同 Windows 版本的 SDK 差异
  • 隐藏 SSID：uSSIDLength = 0 的 BSS 单独保留并标记「隐藏」，仍可看到 BSSID / 信道 / 带宽 / RSSI / 加密 —— 这正是排查「谁在占信道」最需要的信息

评估：三个容易算错的地方

  • 射频归并：一台 AP 会广播多个 SSID，BSSID 只差最后一字节。按 BSSID 前 5 字节 + 频段 归并为「物理射频」，干扰只计一次；否则一台 AP 挂 6 个 SSID 会被算成 6 个干扰源
  • 噪声与干扰分开：SNR 只用热噪声（-174 dBm/Hz + 带宽 + 7 dB NF，20/40/80/160 MHz 分别 -94/-91/-88/-85 dBm）；SINR 才叠加干扰功率 × 占空比（占空比取 BSS Load，缺失按 30%）。混在一起会把「同频争用」误报成「噪声底 -33 dBm」
  • 重叠按频率区间算：每个 BSS 展开成 [中心频率 ± 带宽/2]，两段区间重叠 ≥50% 记同频；2.4G 再按 ±1/-3 dB、±2/-10 dB、±3/-20 dB、±4/-30 dB 补邻频。用「信道号相减」判宽信道会算出 156/160 这种不存在的信道

输出指标

  • 区域总分（0-100）＝ 覆盖 35% + 干扰 35% + 安全 15% + 2.4G 密度 15%，分优/良/中/差/很差五档
  • 每个 SSID：最强 RSSI、SNR、SINR、同频/邻频射频数、信道利用率、加密强度、质量分（SINR 55% + 同频争用 20% + 利用率 15% + 绝对信号 10%）
  • 每个信道：BSS 数 / 射频数 / 活跃射频数 / 重叠对数 / 利用率 / 干扰指数 0-100（射频数 45% + 重叠对 20% + 利用率 35%）与等级
  • 整改建议：每频段推荐 3 个最干净信道；问题清单按严重度给出（干扰信道、2.4G 过密、开放网络、隐藏 SSID、80 MHz 宽信道）

与已有模块的关系

  • 扫到的 SSID 可勾选后 一键导入为全局分析对象（source=scan），带本次采集点最强 RSSI 作为备注
  • 新建 / 编辑 / 删除 SSID 后自动重建模拟终端池，任何新 SSID 都会分到终端，按 SSID 筛选不再是空表（修复「新建 SSID 无法使用」）
  • 真实扫描数据不写入热力图：热力图仍按图纸坐标与传播模型算，二者口径不同，混用会得出错误结论；后续 P1 可用扫描结果校准路径损耗指数
边界：① 单台笔记本扫描是单点测量，换位置结果会变，判定整层需 2-3 个点位；② 隐藏 SSID 的名称在空口上不传输，无法还原（我们只报 BSSID / 信道 / 信号），要真名需控制器端查询或定向探测；③ 扫描会让网卡短暂切换信道，可能造成 1-2 秒瞬断，生产终端上请避开业务高峰；④ 有线环境、网卡被禁用、WLAN 服务未启动时无法扫描，界面会给出对应提示；⑤ 全程只读，不连接、不改配置、不上传，不调用任何外网接口。

16.13 移动漫游监测：边走边看当前 SSID、漫游与信道拥挤（v0.13）

16.12 解决「站在一个点看环境」，本节解决「带着电脑走动看体验」：按路线走一遍，实时出现当前所在 SSID / 接入点、每次漫游（从哪个 BSSID 切到哪个、切完信号多少、停留多久）、掉线区间，以及所在信道的拥挤程度。数据仍然是本机真实无线网卡，只读。

采集：两层频率，互不干扰

  • 高频层（默认 1 秒）：netsh wlan show interfaces 轻量轮询，拿当前关联的 SSID / BSSID / 信道 / 频段 / 信号 / 收发速率；netsh 报 dBm 时直接用，只有百分比时按线性口径换算并标注「百分比换算」
  • 低频层（默认 20 秒）：读系统 BSS 缓存算周边与信道拥挤；缓存不足 6 个 BSS 时自动补一次主动扫描（≥15 秒限速一次），避免高频触发 WlanScan 干扰被测漫游本身
  • 扫描窗口标记：主动扫描会让网卡短暂切信道，可能产生假掉线 / 假漫游；窗口起止时间记入记录，落在窗口内的事件标注「可能是扫描伪影」，判读时剔除

判定与产出

  • 漫游分类：同 SSID 换 BSSID＝二层漫游；换 SSID＝跨 SSID 切换；换频段＝跨频段漫游；关联消失＝掉线，恢复时记空窗时长
  • 每条漫游记录：from → to（BSSID / 信道 / RSSI）、旧 AP 驻留时长、观测空窗（≤ 采样间隔，非空口时延）、信号变化 dB、是否落在扫描窗口
  • 粘滞检测：当前信号 ≤ -72 dBm 且停留 ≥ 20 秒，同时同 SSID 存在强 ≥ 8 dB 的邻居 BSSID 未切换 → 提示 802.11k/v 未启用、漫游门限过高或驱动策略保守
  • 输出：信号轨迹图（含 -67 / -75 阈值线与切换时刻标记）、漫游时间线、漫游体验分（掉线 / 切换后弱信号 / 空窗 / 当前信道拥挤加权）、同 SSID 邻居表、当前信道拥挤指数与本频段排名、CSV 导出留档
边界：① 采样间隔就是漫游判定分辨率，「切换耗时」是两次观测的差，不是空口抓包级时延；② netsh 信号百分比换算的 RSSI 分辨率约 2 dB，不用于精细比较；③ 周边 BSS 为系统扫描缓存，主动扫描后才新鲜；④ 只测本机这一张网卡，手机 / PDA 漫游行为可能不同，同一台机器按固定路线多走两遍对比 CSV 更可信；⑤ 全程只读，不连接、不断开、不改配置、不联网。

  • 同时输出置信度场：按到最近实测点的距离衰减，远处颜色淡化，明确提示「未勘测区域」
  • 四图层：RSSI、SINR（缺失时回退 SNR）、干扰指数（反向着色）、需求达标（绿 / 黄 / 红离散三色）

  • 输出拟合前后 RMSE、平均绝对残差、异常点清单；护栏：改善 < 0.5 dB 或拟合值落在搜索边界时提示不要采用

16.16 智能审计：自动问题清单、信道规划与安全核查（v0.14）

新增第 13 页「智能审计」，把散落在空口扫描、勘测验收、漫游监测里的异常汇总成一张按严重度排序、每条都带证据和处置动作的清单，对应 AirMagnet AirWISE 的产品思路。

规则库（10 类）

  • 覆盖验收 / 勘测完整性：不达标点位数、点位少于 5 个时置信度告警
  • 信道规划 / 干扰 / 容量：2.4G 非 1/6/11、2.4G 射频过密、最忙信道指数 ≥55、80 MHz 以上带宽、BSS Load ≥70%、DFS 信道
  • 安全 / 核查：开放网络、WEP/TKIP 弱加密、同名 SSID 多套加密配置（仿冒热点嫌疑）、未登记 SSID 核对、隐藏 SSID、SSID 数量过多
  • 漫游：监测期掉线、粘滞终端（弱信号 ≥20 秒且有强 8 dB 邻居未切）
  • 每条输出：编号、严重度、分类、标题、证据数组、影响说明、处置步骤数组、关联章节

评分与规划口径

  • 健康分 = 100 · exp(-Σ扣分 / 75)，扣分：严重 18 / 高 11 / 中 6 / 低 3；用指数衰减避免问题一多就一律归零，保留区分度
  • 2.4G：只保留 1/6/11、20 MHz、功率 11–14 dBm，与 5G 保持 6–9 dB 差引导双频终端；5G：高密 40 MHz / 低密 80 MHz、14–17 dBm，语音与定位业务迁出 DFS
  • 「覆盖射频」按频率区间统计，40/80 MHz 会覆盖多个 20 MHz 信道号；判「非规划信道」时只认 BSS 中心落在该信道的行，否则会把所有相邻行误报
  • 安全核查内置常见 OUI 前缀表；BSSID 本地管理位为 1 时判「随机 / 私有 MAC」，不用于厂商识别
实测踩到并已修正的三个误报：① 2.4G 相邻信道因频率覆盖被当成「AP 用了非 1/6/11 信道」→ 改为只按 bss_on_channel > 0 判定；② 邻近单位 / 私接热点的 SSID 一律被标成高危「非法 AP」→ 降为低等级「核查」，并注明空口无法判断 AP 是否接入内网；③ WPA2-TKIP 因字符串含 WPA2 漏过弱加密检查 → TKIP 单独命中。这三条说明审计规则必须放在真实空口数据上跑，不能只做单元测试。

16.17 勘测报告、数据持久化与硬边界（v0.14）

离线交付物

  • 勘测报告：/api/survey/report 生成单文件 HTML（内联 CSS、零外链），7 节 = 执行摘要 / 逐点验收明细 / 自动问题清单 / 信道规划 / 安全与合规审计 / 传播模型校准 / 数据口径与能力边界，含封面信息、验收模板原始口径与三方签字栏，浏览器直接打印成 PDF
  • 点位 CSV：26 列带 UTF-8 BOM，含判定结果与不达标原因，可直接进 Excel 或归档；热力图 PNG 与漫游 CSV 沿用既有导出
  • 报告与界面文案同步列出：所用阈值、扫描时间、点位数量、健康分算法、能力边界，避免「黑箱数字」

必须如实告知的边界

  • 硬件代差：Ekahau Sidekick / AirMagnet Spectrum XT 有专用射频前端，能出实时 FFT 频谱并识别蓝牙、微波炉、雷达、无线摄像头等非 Wi-Fi 干扰源；普通笔记本网卡只提供 Beacon/Probe 解析，本软件的干扰指数是「可见射频数 + 频率区间重叠 + AP 上报 BSS Load」的工程估计，不做原始频谱分析
  • 单点测量：一次扫描只代表该时刻该位置；整层结论需多点位（建议 ≥15 个）采集，并避开业务高峰
  • 隐藏 SSID：名称在空口上不传输，无法还原；厂商由 OUI 前缀推断，随机 MAC 不能用于此判断
  • 只读：不连接、不断开、不改配置、不发包测速、不上传、不调用任何外网接口；主动扫描会让网卡短暂切信道，可能 1–2 秒瞬断
  • 未接现网：未轮询 SNMP / WLC API，读不到真实发射功率、关联终端数与历史告警；相关字段均为 Beacon 中 BSS Load 估计或留空
后续路线（未开始）：① 多点采集汇总成楼层级干扰热区图；② 同一路线优化前后报告自动 diff；③ 项目级多楼层管理；④ 在用户显式授权、且明确「只读或最小探测」边界后，再评估网关 / DNS 连通性与时延的主动测试；⑤ P1 接 SNMP / 控制器 API 后，把审计规则里的「AP 上报利用率」换成真实统计。

16.19 不依赖专用硬件的软件能力补齐（v0.16）

v0.14 用「专用频谱硬件」与「控制器配置下发」两条边界划出了与 Ekahau / NetAlly AirMagnet 的代差。v0.16 按「只要不依赖他们硬件，能做的都应该做进去」的要求重新审视这条边界，发现原来的划法太粗：把三类性质完全不同的限制混在了一起，容易让人误以为在拿硬件当借口。本节按现场能落地的口径重切为四类，并说明各自的处理方式。

四类边界与处理

  • ① 硬件级（真做不了）：实时 FFT / IQ 采样、蓝牙 / 微波炉 / 雷达等非 Wi-Fi 干扰源识别、认证级射频测量。需专用射频前端，普通网卡只有 Beacon/Probe；界面与报告继续如实标注
  • ② 定位 / 授权级（能做，但不是硬件问题）：SNMP 只读轮询现网设备、WLC/AP API、信道功率配置下发、主动吞吐 / 时延 / 丢包测试。卡在「离线、只读、零外网、数据不出本机」这条产品定位，需用户显式授权才改；本版维持关闭，不擅自放开
  • ③ 数据 / 模型级（能做，但缺输入）：3D 射线追踪、多层楼板与 3D 天线方向图、AI 式诊断、图片自动识别墙体。缺楼板结构 / 材料参数、厂商方向图、标注样本，硬做就是假精度。本版只做有确定输入的 ASCII DXF 导入 + 人工修墙
  • ④ 纯软件工程量（无借口，全部补齐）：报告模板、多楼层合订、优化前后 diff、CSV 批量导入、图层扩充、审计规则自定义、走测路径、深色主题

  • 多楼层合订：楼层台账（名称 / 实际宽度 / 备注）登记后自动切换为同名勘测会话；勾选多个会话生成合订报告，逐会话独立计算点位与达标率后汇总，不混点插值
  • 优化前后对比：基线快照固化验收结论、健康分、问题清单与逐点数据；对比输出 9 项指标的 Δ 与改善 / 退化判读、问题新增 / 消除 / 改级、按点位名称配对的 ΔRSSI / ΔSINR，可写进报告第 9 章
  • 点位 CSV 批量导入：中英文表头映射 20+ 字段，坐标夹到 1000×700，缺坐标行跳过并报行号；提供模板下载
  • 实测图层 4 → 8：新增 SNR、干扰余量损耗（SNR−SINR）、可见射频数、信道利用率；配色按各图层 min/max 归一，反向指标（干扰 / 利用率 / 余量损耗）自动反向着色
  • 审计规则自定义：16 条规则逐条启停 + 严重度覆盖，recompute_audit() 统一重算健康分 / 等级 / 计数；界面、报告、快照共用同一口径

16.21 热力图渲染与绘制体验优化（v0.18）

v0.17 之后，采集、打点、验收、诊断、报告这条数据链已经闭环，本轮不再增加数据来源，而是处理两件之前被推迟的事：同一份计算结果能不能被一眼读懂，以及没有图纸时画出来的草图能不能画得准、画得顺手。全部改动集中在前端 app.js / index.html / style.css，后端传播模型、残差校正、统计指标与任何报告数字都不变——这是一次「表达层」升级，不是算法升级。

① 渲染质量：从「低分辨率先着色再放大」到数值域插值

  • 平滑色带：旧做法在 cols × rows 网格上先映射 RGB，再由浏览器把小图放大到 1000×700，插值的是颜色，色带交界会出现阶梯块。新做法先在数值域做双线性插值到 2× 网格，再逐像素映射颜色，最后只放大 2 倍；标准网格 120×84 → 240×168，精细网格 160×112 → 320×224，单次重绘仍在一帧量级。可勾选关闭以对比原始网格颗粒
  • 动态色标：右侧色标由固定 7 段改为按色标函数采样 32 段；RSSI 图层用 dBm 刻度，切到「有效 SINR」图层自动换成 dB 刻度；门限标记取自当前 SSID 的 min_rssi（实测 SAFRAN 为 −70 dBm），不再是写死的 −67；SINR 图层显示 20 dB 可用参考线。窄栏里改为「两端量程 + 居中门限」两行，避免文字挤压
  • 等值线：用 marching-squares 在网格数值上求覆盖门限线与 −80 dBm 盲区边界线，格点按后端采样位置 (c+.5)×cell_w 对齐，与色块中心一致；鞍点按双线段处理，线旁标注门限值；两者可分别开关
  • 不透明度：10–100% 滑块控制整个热力图层（默认 72%，保持原有观感），调淡后可看清底图墙线做人工修墙
  • 导出 PNG：旧版把 heat 画布按 100% 不透明合成，导出图比屏幕更浓。新版按滑块同一系数合成，并内嵌 24 段色标、量程、门限、网格精度、传播模型与生成时间；脱离软件后仍能读数

② 绘制交互：所见即所得

  • 实时尺寸：画房间显示 宽 × 高 m，画隔墙显示 长度 m · 角度°，比例尺标定显示当前线长换算米数并提示松手后输入实际长度；深色小标签跟随鼠标、自动避开画布边缘
  • 端点吸附：除网格吸附外，靠近已有墙 / 房间角点 13 px 内优先吸附到该端点并用橙色十字高亮，避免新墙与旧墙差几个像素形成缝隙；skAllWalls() 端点按 3 px 量化去重
  • 门洞预览：「开门洞」工具悬停即高亮目标墙（蓝色半透明）、画出按 0.9 m × ppm 换算的橙色开口虚线并标注宽度，点击前即可确认开在哪面墙
  • 两处一致性缺陷：① 旧版 skUp 用原始鼠标点 skClamp(p) 落笔，而拖拽预览用的是吸附 / 正交后的 drag.cur，导致「看到的」与「画出来的」不一致；现统一用 drag.cur。② 画房间分支完全没有对终点做网格吸附，现随同一逻辑修正
  • 性能：mousemove 的编辑层重绘与拖动 AP 的轻量预览合并到 requestAnimationFrame 一帧，避免高频事件重复全量绘制三个 1000×700 图层

口径与边界（必须如实告知）

  • 平滑只是视觉插值：网格数值、覆盖率、盲区占比、低置信区、RMSE、健康分等所有指标一律不变；关掉开关即可看到原始网格，便于复核
  • 等值线是模型网格插值出的门限位置，不是实测走测边界；它与热力图同源，因此不会给出与色块矛盾的结论，但精度受网格分辨率限制（标准 120×84 ≈ 8.3 px/格）
  • 动态门限来自 SSID 配置的人工填写值，不是控制器下发或空口协商结果；SINR 的 20 dB 是工程参考线，不是协议门限
  • 草图仍是示意草图、墙为零厚度线段、材质损耗取经验值；实时米数依赖用户标定的比例尺，标定不准则标注也不准。导出 PNG 是位图，不是可编辑 CAD 图层
  • 本轮未触碰「离线、只读、零外网、数据不出本机」定位；SNMP / WLC API / 主动业务测试 / 配置下发仍需单独授权，非 Wi-Fi 频谱 FFT 仍受硬件限制
